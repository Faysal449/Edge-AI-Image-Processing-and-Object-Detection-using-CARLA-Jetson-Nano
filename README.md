# Edge-AI Image Processing and Object Detection using CARLA & Jetson Nano

## Overview

This project implements a Distributed Edge-AI Hardware-in-the-Loop (HIL) simulation framework for autonomous vehicle perception. A CARLA simulator running on a Windows PC generates RGB camera frames and streams them over a real local network to an NVIDIA Jetson Nano edge device for real-time AI inference.

The Jetson Nano performs TensorRT-accelerated object detection using **SSD-MobileNet-V2** and **YOLOv8** at FP16 precision. Detection results are returned to the PC through a JSON feedback channel, while latency, jitter, frame delivery, and inference timing are recorded for performance analysis.

The objective is to replicate a realistic autonomous vehicle perception architecture, where sensor data is generated by a simulator but processed on real embedded edge hardware under practical network conditions.

## Communication Pipeline

### Frame Transmission (PC Side)

* CARLA generates RGB camera frames from the simulated vehicle camera
* Frames are converted from raw CARLA image format into OpenCV-compatible arrays
* JPEG compression is applied using OpenCV
* Each frame is transmitted through TCP or UDP socket communication
* A timestamp is added before transmission for latency measurement

**Packet Structure:**

```text
| Frame ID | Send Timestamp | Payload Size | JPEG Image Data |
```

At the primary benchmark setting of **320 × 240 pixels** and **JPEG quality 60**, each compressed frame is approximately **8–15 KB**, allowing the frame to fit into a single UDP datagram.

### Frame Processing (Jetson Nano)

* Receive frame through TCP or UDP
* Extract frame ID, timestamp, and payload size
* Decode JPEG image using OpenCV
* Convert image format for Jetson inference processing
* Transfer image to CUDA memory
* Run TensorRT object detection
* Send JSON feedback containing detection results and timestamps back to the PC

## AI Models (Jetson Nano)

| Feature                | SSD-MobileNet-V2 | YOLOv8          |
| ---------------------- | ---------------- | --------------- |
| Dataset                | MS COCO          | MS COCO         |
| Classes                | 91               | 80              |
| Runtime                | TensorRT         | TensorRT        |
| Precision              | FP16             | FP16            |
| Input Size             | 300 × 300        | 640 × 640       |
| Average Inference Time | 35.6 ms          | ~70 ms          |
| Approx. Throughput     | ~28 FPS          | ~14 FPS         |
| Strength               | Lower latency    | Higher accuracy |

**SSD-MobileNet-V2** was selected as the primary benchmark model because its lower and more stable inference time makes it suitable for real-time latency analysis.
**YOLOv8** provides higher detection accuracy but requires approximately double the inference time, reducing available performance headroom on the Jetson Nano.

## Key Results

### 200-Frame Primary Benchmark

| Metric             | TCP      | UDP      |
| ------------------ | -------- | -------- |
| Average RTT        | 137.7 ms | 72.2 ms  |
| Median RTT         | 105.9 ms | 59.0 ms  |
| Minimum RTT        | 54.4 ms  | 51.9 ms  |
| Maximum RTT        | 555.3 ms | 313.1 ms |
| Standard Deviation | 89.4 ms  | 41.2 ms  |

UDP achieved a **47.6% lower average round-trip time** than TCP in the primary benchmark.
This shows that UDP is more suitable for real-time camera frame streaming, where receiving the newest frame quickly is more important than guaranteeing delivery of every old frame.

### Inference Performance

| Model            | Average Inference Time | Approx. Throughput | Main Advantage  |
| ---------------- | ---------------------- | ------------------ | --------------- |
| SSD-MobileNet-V2 | 35.6 ms                | ~28 FPS            | Low latency     |
| YOLOv8           | ~70 ms                 | ~14 FPS            | Higher accuracy |

TensorRT FP16 inference on the Jetson Nano was highly stable. SSD-MobileNet-V2 achieved an average inference time of **35.6 ms** with very low variation, making it suitable for the 10 FPS camera stream.

### 500-Frame Stress Test

The stress test used **640 × 480 resolution at 30 FPS**, which pushed the system beyond the Jetson Nano’s sustainable processing capacity.

* TCP entered buffer saturation and became unsuitable under overload
* UDP dropped frames but continued processing successfully delivered frames
* UDP degraded more gracefully than TCP under high load
* The test confirmed that **320 × 240 at 10 FPS** is the stable operating point for this Jetson Nano setup

## Key Insights

* UDP is the better choice for real-time camera frame streaming because it provides significantly lower latency than TCP.
* TCP remains useful for reliable structured feedback, where JSON detection results and timestamps must arrive correctly.
* TensorRT FP16 optimization is essential for achieving real-time inference on the Jetson Nano.
* SSD-MobileNet-V2 is better for low-latency edge-AI benchmarking, while YOLOv8 provides higher accuracy at the cost of higher inference time.
* A multi-threaded sender design with a queue size of 1 prevents artificial frame backlog and keeps latency measurements realistic.
* TensorRT warm-up creates large first-frame latency spikes, so longer benchmarks are needed to measure steady-state performance correctly.
* The Jetson Nano is stable at 320 × 240 and 10 FPS, but higher resolution and higher FPS require stronger hardware or further optimization.

---

## Limitations

* Experiments were mainly performed on a local WiFi network
* The system focuses on perception benchmarking, not full closed-loop vehicle control
* Jetson Nano has limited performance at higher resolution and frame rate
* One-way latency measurement can be affected by clock synchronization between PC and Jetson Nano
* ROS2 integration was not included due to Jetson Nano software compatibility and middleware overhead considerations
